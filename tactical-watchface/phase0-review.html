What verification changed

Checked against Google's XSD schemas and validator source, not from memory.

Available

Day of year is native

DAY_OF_YEAR is a v1 data source, and so is ISO week. The spec's fallback plan for computing DOY from month and day is not needed.

Available

Step goal needs no complication

STEP_PERCENT and BATTERY_PERCENT drive both arc gauges directly. BATTERY_IS_LOW gives the red state a real system flag instead of a hardcoded 15%.

Available

Weather has a real unavailable state

WEATHER.IS_AVAILABLE and WEATHER.IS_ERROR exist, so the phone-disconnected case can be built properly rather than guessed at.

Needs care

No second time zone source

Every WFF time source reads local time. Zulu is still buildable — UTC_TIMESTAMP is epoch-based, so UTC and any fixed offset come out of arithmetic. Its units are unconfirmed; I check that on your watch before wiring it.

Not available

No sunrise/sunset, calories, distance or floors

The health sources are steps and heart rate, full stop. Sunrise/sunset exists only as a system complication provider — it can fill a slot, but it cannot mark the outer track the way the spec imagined.

Not available

No compass, altimeter, barometer or GPS

Only the accelerometer is exposed, and it gives tilt, not heading. Nothing to fake, which is how the spec wants it.

Needs care

Google's validator still caps at WFF v4

The v5 schemas have shipped but MAX_WFF_VERSION is still 4. Targeting v5 today means building without the automated gate the spec requires on every build. This is why question 10 has a real answer rather than a preference.

Needs care

Panel resolution unconfirmed

These are drawn at 498×498 from published specs. The spec is explicit that it must be read off the hardware — first ADB command in Phase 1. Every position is a fraction of the radius, so a different panel rescales cleanly.

Thirteen questions

Answer any subset. Anything you skip, I take the recommendation.

00

Where should this project live?Not in the spec

This branch is on the MD Weather Alerts repo, which already holds a different product. A watch-face CLAUDE.md at that root would misdirect every future session there, so for now everything sits in a tactical-watchface/ folder.

Recommendation

A new dedicated repo — the folder moves across wholesale and nothing else changes. You would create the empty repo; I do the rest. Keeping it where it is also works, it is just untidy.

01

Which design direction?

A, B, C, or a combination — mixing is fine. A's layout with C's in-cell progress bars would work, for instance.

Recommendation

A — SECTOR. Most real data per glance without crowding, the best ambient mode, and the one-accent-one-job discipline holds cleanly. C is the most legible but the least distinctive; B's hand-over-label problem is above.

02

What is it called?

Store name and on-watch name. One or two syllables, no "Pro", and no "Tactical" in the name itself.

Recommendation

SECTOR, MERIDIAN, or VECTOR — I would ship SECTOR. I will check the Play Store for collisions once you shortlist.

03

Default accent colour?

Eight ship regardless — Phosphor Amber, Signal Orange, Safety Yellow, NVG Green, Ice, Cobalt, Coral, Bone — plus a Mono theme. This is just what it looks like out of the box.

Recommendation

Phosphor Amber if you want this to feel like a family with your Garmin TELEMETRY face; otherwise Signal Orange. Both accents are rendered above — use the toggle.

04

24-hour default? Seconds shown by default?

Recommendation

24-hour, seconds as the sweeping arc. Both stay configurable — 12/24h, leading zero, and Arc / Digits / Off.

05

Secondary time zone — UTC fixed, or selectable offset?Changed by verification

WFF has no second-time-zone data source, so this is expression arithmetic on the epoch timestamp rather than a built-in field. Buildable either way.

Recommendation

Ship UTC/Zulu first, add a selectable offset in Phase 4. One caveat: I could not confirm whether the timestamp is in milliseconds or seconds, so I verify that on your watch first. Fallback if it turns out unworkable is a World Clock complication — real, but less elegant.

06

Which three data fields, and in what order?Changed by verification

The picker list has to shrink to what exists: steps, step goal, heart rate, battery, weather, moon phase, notification count. No calories, distance or floors — those can only arrive through a complication slot.

Recommendation

STEPS · HR · BATT. Note the order is not the spec's. Listing HR first puts the steps value in the centre while the step gauge sits on the left edge; reordering pairs each gauge with the number directly inboard of it, so an unlabelled arc is unambiguous.

07

Left and right gauge defaults?

Recommendation

Left = step goal in the accent, right = battery in neutral white, turning red when low. Both drive natively; no complication needed.

08

How many complication slots, and where?

Recommendation

For A: one, bottom centre, weather by default. The spec suggests up to three. I would rather ship one excellent slot and add side slots in Phase 4 if it feels sparse on your wrist. B has the two round slots at 3 and 9; in C all four cells are slots.

09

Which nice-to-haves do you want?

Night Ops (everything dimmed ~35%, accent shifts to deep red) · Flavors (one-tap presets in the Galaxy Wearable app) · Notification count · Moon phase · Sunrise/sunset · Alarm indicator.

Sunrise/sunset is complication-only. I found no alarm data source at all — treat it as unavailable unless it turns up.

Recommendation

Yes to Flavors and Night Ops, yes to notification count; skip moon phase and sunrise/sunset for v1. They earn their place on a hiking face, less so on this one, and all are easy to add later.

10

WFF v4 or v5?Changed by verification

Not really a preference any more — see the validator finding above.

Recommendation

v4. It also reaches far more devices (Wear OS 6+, so Pixel Watch and Galaxy Watch 4 onward), and none of the v5-only features are needed by any of the three directions. Raising it later is a one-line manifest change plus a re-test.

11

Package name?

This can never be changed after first publish, so it is worth a moment.

Recommendation

com.mdweatheralerts.watchface.sector — reusing the domain you already own, which keeps it verifiable and consistent with your existing Play Console app. If you would rather this not sit under the weather brand, give me another domain you own.

12

Broader device QA, or Ultra 2 only for v1?

Recommendation

Ultra 2 primary, plus one round Wear OS 6 emulator check before publishing. The face gets listed for other round devices so it should not look broken on them, but they are not worth a full test matrix for v1.
